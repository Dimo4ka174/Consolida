# Известные компромиссы и техдолг

Документ — честный список того, что в проекте можно было сделать иначе,
но оставлено осознанно. Это не «todo-лист», а зафиксированные решения
с обоснованием.

---

## 1. SelectListItem в Application

**Что не так.** `ProductDto.ManufacturersList` — это `List<SelectListItem>`,
тип из ASP.NET Core MVC. Бизнес-слой знает про web-фреймворк.

**Почему оставлено.** Проект монолитный, переиспользование `Application`
вне web (консоль, desktop, WASM) не планируется. Введение своего
`SelectItemDto` + маппинга во вьюхах — плюс один слой бойлерплейта.

**Как правильно.** Свой `SelectItemDto`, конвертация во вьюхе через
extension-метод.

---

## 2. EF.Functions.ILike в Application

**Что не так.** `ProductService`, `OrderListService`, `OrderNotificationService`
используют `EF.Functions.ILike` из Npgsql. Это привязка к конкретной СУБД.

**Почему оставлено.** SQLite и SQL Server требуют другого синтаксиса
(`COLLATE NOCASE`, `LIKE` + `LOWER`). Реализация `ISearchService`
с разными провайдерами — отдельная задача.

**Почему важно знать.** `ILike` не транслируется в `MockQueryable` — тесты
на этих методах не писались. В новом коде используется
`Contains` / `StartsWith` / `EndsWith` — они транслируются любым провайдером.

---

## 3. CalculationService смешивает загрузку и вычисления

**Что не так.** `BuildCalculationViewModelAsync` сам тянет данные из БД
и сам считает. Сложно тестировать без моков `IUnitOfWork`.

**Как правильно.** Разделить на два компонента:

- `ICalculationDataProvider` — только загрузка (заказы, налоги, коды ТН ВЭД).
- `CalculationCalculator` — чистые функции без зависимостей.

Тогда расчёты тестируются без моков вообще.

**Оценка.** Около одного дня рефакторинга.

---

## 4. Дублирование расчётов на C# и JS

**Что не так.** Формулы расчёта дублируются в `CalculationService` (C#)
и в `wwwroot/js/order/details/calculation/` (JS).

**Почему оставлено.** Клиентский пересчёт нужен для интерактивности —
гонять запрос на сервер на каждый keyup нельзя.

**Как правильно.** WASM-модуль с общими формулами, вызываемый и с клиента,
и с сервера. Для пет-проекта избыточно.

---

## 5. Тесты не покрывают ILike-методы

**Что не так.** `ProductService.GetFilteredPagedAsync`,
`OrderListService.GetOrdersAsync`, `OrderNotificationService.SearchOrdersAsync`
не покрыты тестами.

**Причина.** `MockQueryable` не поддерживает `ILike`. Покрывать их можно
только integration-тестами на реальном Postgres.

**Решение в будущем.** Замена `ILike` на `Contains` + `ToLower()`
(см. пункт 2) откроет путь к тестам.

---

## 6. Метрики Prometheus + Grafana отсутствуют

**Что не так.** Serilog пишет в файл, метрик нет.

**Почему оставлено.** Пет-проект не работает под нагрузкой. Метрики
имеют смысл при реальной эксплуатации.
